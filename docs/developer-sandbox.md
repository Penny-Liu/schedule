# 開發沙盒

系統管理員可在人員管理的編輯表單勾選「開發沙盒（僅本機模擬）」並儲存，下次登入生效。功能頁面仍依帳號原有權限開放；此設定本身不授予額外功能權限。

沙盒將一般資料表的新增、修改、刪除與 upsert 模擬在記憶體中，再次查詢會合併模擬結果。修改不會送往正式資料庫，也不會保存到 localStorage。重新整理、登出或關閉頁面即丟棄這些模擬資料。登入後會持續顯示黃色提示。

資料同步、遠端函式、儲存空間上傳及不支援的查詢會顯示阻擋訊息，不會退回正式寫入。唯一例外是本人個人密碼設定：驗證目前安全登入身分及正式人員對應後，更新正式安全登入密碼與該人員的 `password`、`must_change_password` 欄位，重新整理後仍有效。首次登入修改與個人設定共用此流程；其他人員的密碼重設仍只模擬。尚未綁定安全登入的沙盒帳號不能使用此例外。伺服器約束、觸發器、關聯級聯刪除與預設欄位值不保證完全重現；需驗證這些行為時使用獨立測試資料庫。

帳號設定使用既有 `users.permissions` 的 `developer_sandbox` 標記，無需新增資料庫欄位。模擬期間即使在畫面中取消自身標記，本次沙盒也不會解除。

## 使用界線

這是網站內的操作模擬功能，不是資料庫安全權限。現行部分資料表允許公開 API 寫入；直接呼叫 API、修改網頁程式或使用舊版程式，不受此功能保護。對資訊人員提供正式 API 存取或實際程式開發環境時，須使用獨立測試資料庫及相應權限，不能單靠此勾選項保護正式資料。

## 驗證

自動測試透過真實 Supabase SDK 與假傳輸層，驗證本機 CRUD、重讀、複合鍵 upsert、篩選及分頁，以及不支援操作的攔截。

本機瀏覽器使用隔離假資料測試：登入沙盒帳號 → 人員管理 → 建立模擬人員 → 切頁返回仍可見 → 重新整理後清除。測試 API 記錄的資料寫入請求為零；沒有修改正式帳號設定。
