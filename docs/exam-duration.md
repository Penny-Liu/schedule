# 放射師檢查耗時

## App 操作

放射師 → 統計 → 檢查耗時。可用共同週期、個人週期或自訂日期；可篩選院區、設備、檢查類別與工作量分類。

- 個人檢視：各項耗時、排程平均、全科平均、高於／低於平均的分鐘數、有效樣本、來源流程與覆蓋率。
- 全科比較：人員 × 檢查分類矩陣；點人名進入個人檢視，點數值查看計算依據。單一分類提供橫條圖及全科平均線。
- 原始明細：保留單項、流程與均攤數值。來源品質明細不將衍生均攤、來源流程或排程加作檢查量。

姓名、指定分類耗時、完成量、有效樣本、來源流程與覆蓋率可正反序排序；無有效時間或不合格的 MR 在耗時排序排最後。排序不代表績效評分。

## 完整 MR 流程與女大套

演算法 `actual-flow-v3`：已完成的 MR 主預約，依同日、同張 Order、同院區合併。不同日期、院區及 Order 絕不合併；缺少 Order 時保留獨立來源。

各段使用 examination_StartTime1__c／examination_EndTime1__c，合併區間聯集：扣除重疊，排除段落間空檔。任何一段時間缺漏、格式錯誤、零值、負值或超過四小時，都不把剩餘部分冒充完整流程。多位執行者或性別矛盾時不歸屬其中一人。跨設備以合併名稱呈現。

MR 按完整流程的不同檢查項目分套別：小 1～3、中 4～6、大 7 項以上。女性大型套另核對是否含乳房／breast 醫令：含乳房為 mr大女，未含乳房另列 mr大女（未含乳房），不混作同一套別比較。乳房另開主預約時，其時間會合併進同次完整 MR，不再獨立誤列為小套。

排程由 StartTime__c／EndTime__c 計算，另存 planned scope；同一排程被多段沿用時也以聯集去重。畫面並列排程平均與紀錄耗時，兩者樣本數及有效性分開計算。排程 90 分不會代入實際耗時。

原始 MR 主預約紀錄不一定等同純掃描時間；報到／開始／完成操作時機仍會影響時間，可能包含準備與等候。

## 其他計時與均攤

只讀取 CheckupReservation__c 已完成（End__c=true）且狀態為 10 的 MR／CT／US／BMD／MG／DX。單項及非 MR 流程保留原始口徑；CTA 使用對應整次流程。後處理使用 CTA_Further_Rad__c 與 CTA_Further_StartTime__c／CTA_Further_EndTime__c，不混入掃描流程。CTAUseTime__c 僅作分類標記。

均攤估計＝完整流程紀錄時間 ÷ 該流程已完成醫令筆數。排除報到、未完成、其他類別、後處理及重複 ID。MR 使用合併後完整流程；US 子部位依實際子醫令分類。跨次平均為總時間除以總有效醫令數，不能直接平均各次比值。此為估計，不是每項獨立實測。

Scope：item（單項）、flow（流程）、allocated（均攤醫令）、allocation_flow（獨立來源流程）、planned（MR 排程）。均攤醫令與來源流程不能相加成檢查量；US 同流程各部位的來源也不能跨部位相加為獨立人次。

## 全科平均與 LINE

MR 套別與 CTA 比較每次流程分鐘，後處理比較獨立計時，其餘比較每醫令均攤估計。全科平均按同一分類、同一口徑的有效樣本加權，包含本人；選取一人不縮小全科基準，日期／院區／設備篩選會改變基準。

MR 至少 2 次有效來源流程才納入全科平均與比序，少於 2 次反灰標示樣本數不足。US／CT 等有 1 筆有效時間即可呈現。至少有 2 位合格人員才顯示人員差異與 LINE 比序。覆蓋率及未同步提示仍保留。高低差異按畫面一位小數相減。

LINE 只列分類全科平均、由短到長的人員比序與分鐘數；排除樣本不足、無有效時間及沒有其他人可比較的分類。顯示時間相同採同名次；個人檢視保留全科比序。預覽與複製共用同一文字。複製沿用 Clipboard API／HTTP LAN textarea fallback；失敗可手動選取預覽。

## 同步

後台同步 → 僅選檢查耗時／第 5 項，選日期後開始同步。可用今日、昨日、本月、最近 45 天、目前所選週期；最多 367 天。完成後在檢查耗時按重新讀取。

開發版需啟動 npm run dev:all，透過 loopback 同步後端及 Vite proxy。正式版透過現有 GitHub Actions dispatch；雲端接受請求代表排入背景執行，需等 Actions 完成。前端沙盒保持阻擋正式同步。

本機與 Actions 共用 npm run sync-tasks，依 SYNC_PAYLOAD 選取 1～5 項；僅選 5 不執行其他項。每日預設執行 1、4、5；耗時預設回補最近 45 天。

```sh
# 唯讀稽核
npm run sync-exam-duration -- --from 2026-10-04 --to 2026-11-02
# 寫入統計彙總
npm run sync-exam-duration -- --from 2026-10-04 --to 2026-11-02 --write
```

需要伺服器 Salesforce 憑證與 Supabase service_role，不放入瀏覽器。不修改 Salesforce 原始醫療紀錄。只儲存匿名檢查分類與放射師彙總，不儲存病患、Order 或主預約 ID。

## 資料庫與安全

依序套用 20261105 的耗時 migrations：初始表、flow、allocated、allocation_flow、planned／v3。每日期透過 service_role 專用 RPC 原子取代資料與同步標記，包含零筆日期；舊快照不能覆蓋新快照。RLS 限已登入、有工作量查看權限或系統管理員的啟用帳號；匿名不可讀，瀏覽器不可寫。App 額外核對登入 Auth Id。

v3 畫面不混入舊演算法資料；未回補的日期顯示尚未同步。資料庫 migration 已保存於 supabase/migrations。

## 女大套核對證據（2026-11-05）

修正前第十週期 96 次女性大套混合平均 63.1 分，排程平均 88.3 分，86 次排程為 90 分。39 次乳房另開流程，原只取主段平均 47.4 分，其他 MR 段平均約 34 分；44 次乳房在同一流程平均 80.7 分；13 次未連結乳房平均 50.4 分。這些組別原本混算，不能拿 63.1 分當完整女大套平均。

本次回補後的有效整套人員樣本可能減少：多位執行者共同完成時不歸屬單一人員，不為湊數而分攤整套時間。

修正後第十週期（共同日期）含乳房女大套 89 次整套來源，其中 48 次可唯一歸屬且計時完整，平均 82.4 分、對應排程 90.3 分；套用每人至少 2 次的比序門檻後，5 人共 45 次，全科比較平均 82.2 分。未含乳房另列 13 次，9 次有效，平均 55.8 分，排程 75 分。這些數字僅適用此日期與篩選範圍。
